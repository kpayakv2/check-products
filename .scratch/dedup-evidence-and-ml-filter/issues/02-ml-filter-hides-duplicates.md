## Question

หน้าตรวจซ้ำ (`DeduplicationTab`) ซ่อนคู่ที่โมเดล ML ทำนายว่า "คนละชิ้น" ก่อนถึงมือคน และตัด 100 คู่แรกเงียบๆ — ควรแก้อย่างไร

## ที่มา: ทำไมผู้ใช้ตั้ง 90% แต่ได้ 89 คู่

เกณฑ์ 90% เป็นแค่ขั้น "เป็นผู้สมัคร" ยังมีอีกสามชั้นก่อนถึงคน:

1. **จำนวนสูงสุด** ค่าตั้งต้น 100 (`DeduplicationTab.tsx:62`) — backend เรียงตามความคล้ายแล้วตัด `[:limit]` (`internal_match.py:405-406`) โดยไม่บอกว่าตัดไปเท่าไร
2. **ตัวกรอง ML** `startAudit` (`DeduplicationTab.tsx:67-71`): ซ่อนคู่ที่ `ml_prediction === 'different'` และ `confidence > 0.6`
3. **คะแนนคำนวณสดใหม่** จากชื่อที่ผ่าน `ThaiTextProcessor` ไม่ใช่ค่าเก็บไว้ จึงไม่ตรงกับตาราง `similarity_matches` (24 จาก 89 คู่ที่ผู้ใช้กดไม่อยู่ในรายการ 108 คู่ที่คาดไว้)

89 = จำนวนที่เหลือหลังชั้น 1–2 (อนุมาน: 100 − ~11 ที่ ML ซ่อน; ไม่ได้เก็บผลสแกนครั้งนั้นไว้ จึงยืนยันตรงๆ ไม่ได้) ที่ผู้ใช้กดครบ: merge 76 · keep_both 13

## ข้อเท็จจริงที่ตรวจแล้ว (2026-10-11 หลังผู้ใช้รวมไปแล้ว)

สแกนที่ 90% ไม่จำกัดจำนวนด้วยคำขอเดียวกับหน้าจอ (`POST /api/v1/match/scan-internal`):

- เจอ **250 คู่** · ML ว่า "ซ้ำ" 13 · **ML ซ่อน 225 คู่ (90%)** · เหลือให้ตรวจ 25
- ตัวอย่างที่ถูกซ่อน: `ลับมีด-โค้ง` ↔ `ลับมีด โค้ง` คะแนน **1.000** (ต่างกันแค่ขีด) ML ว่าคนละชิ้น 0.85 · `หกเหลี่ยม9ตัว(หัวบอล)สั้นตราแรด` ↔ `หกเหลี่ยม9ตัว(หัวบอลสั้น)` 0.985
- ในคู่ที่ผู้ใช้เคยตอบ "ตัวเดียวกัน" และยังไม่ถูกรวม **25 คู่ถูก ML ซ่อนทั้งหมด** (+14 คู่ "ไม่แน่ใจ") ⚠️ ห้ามอ่านเป็นอัตราความผิดของ ML — คู่ที่ไม่ถูกซ่อนถูกกดไปหมดแล้ว จึงเหลือแต่คู่ที่ถูกซ่อน (selection bias) บอกได้แค่ว่ามีของซ้ำที่ยืนยันแล้ว ≥25 คู่ที่ ML ซ่อน
- ไฟล์โมเดล `model_cache/feedback_model.joblib` แก้ล่าสุด 2026-10-11 10:20 มีประวัติเทรน 78 ครั้ง · เทรนจากแถว `reviewed=true` ใน `similarity_matches` (`ml_feedback_learning.py:414`) · ตัวกระตุ้นเทรนที่พบ: ปุ่มในหน้า ai-brain (`/api/v1/learn/retrain`) — **ยังไม่ได้ตรวจ** ว่าเทรนจากอะไรครั้งล่าสุดและเกิดอัตโนมัติหรือไม่

## คำถามที่ต้อง grill ต่อ

1. เอาตัวกรอง ML ออกจากหน้าตรวจเลยไหม — backend ตัดคู่ที่กฎอ่านตัวเลขว่า "คนละสินค้า" ไปแล้ว (`is_pair_resolved`) ซึ่งยืนยันกับคนแล้ว; ML ยังจำเป็นไหมเมื่อมีกฎ
2. ถ้าเก็บไว้: ตรวจก่อนว่าโมเดลเรียนจากอะไร (มีข้อมูลที่เครื่องตัดสินเองปนไหม — เคยมี 1,344 แถวที่ป้ายปลอม ถูกปลดแล้ว) แล้ววัดกับคำตอบของผู้ใช้ 569 คู่ ตัวกรองต้องผ่านเกณฑ์ที่ตั้งไว้ล่วงหน้าก่อน
3. เพดาน 100: ควรบอกผู้ใช้ว่า "ตัดไป N คู่" แทนการตัดเงียบ หรือค่าตั้งต้นสูงขึ้น
4. ควรเก็บผลสแกนแต่ละครั้ง (จำนวนผู้สมัคร / ซ่อนโดย ML / ตัดโดย limit) ไว้ให้ตรวจย้อนหลังได้ไหม — ครั้งนี้ตอบ "ทำไม 89" ไม่ได้ตรงๆ เพราะไม่มีบันทึก

## หมายเหตุ

เกี่ยวกับกฎของโปรเจกต์ที่ว่า `reviewed` ต้องหมายถึงคนตัดสิน (CONTEXT.md, `tests/unit/test_reviewed_means_human.py`): ถ้าโมเดลเทรนจากแถวที่ผ่านกติกานั้น ปัญหาไม่ได้อยู่ที่ป้าย แต่อยู่ที่ว่าตัวอย่างน้อยหรือเอนเอียง (คนตัดสินเรียงตามคะแนนสูง)
