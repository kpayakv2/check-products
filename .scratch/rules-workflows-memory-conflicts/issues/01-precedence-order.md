## Question

ในบรรดาชั้นเอกสารทั้งหกนี้ **อันไหนมีอำนาจเหนืออันไหน** เมื่อพูดขัดกัน และ **ข้อความเชิงกฎได้รับอนุญาตให้ปรากฏซ้ำในหลายที่หรือไม่** (ถ้าได้ ภายใต้เงื่อนไขอะไร ถ้าไม่ได้ ที่รองต้องเปลี่ยนเป็นลิงก์ชี้กลับเสมอ)

ชั้นที่ต้องจัดลำดับ:

1. `CLAUDE.md` — ฉบับที่ Claude Code โหลดจริงทุกเซสชัน
2. `GEMINI.md` — รัฐธรรมนูญของเอเจนต์รุ่นก่อน กฎเหล็ก 9 ข้อ (CLAUDE.md มี 7)
3. `START_HERE.md` — เอกสาร "อ่านนี้ก่อน" ที่ระดับราก
4. `.agents/rules/` และ `.agents/workflows/`
5. `docs/` (รวม `docs/CURRENT_STATUS.md` ที่ CLAUDE.md สั่งให้อ่านก่อนเพื่อน)
6. `README.md` — เอกสารที่คนอ่าน ไม่ใช่เอเจนต์

รวมถึงคลังความทรงจำ auto-memory ที่ถูกฉีดเข้าทุกเซสชัน — มันอยู่ตรงไหนของลำดับ เมื่อความทรงจำขัดกับ `CLAUDE.md`

## ทำไมตั๋วนี้เป็นราก

ทุกตั๋วที่เหลือรอคำตอบนี้ ตราบใดที่ยังไม่มีลำดับศักดิ์ การ "แก้" เอกสารที่ขัดกันก็เป็นแค่การเลือกข้างเฉพาะกิจครั้งต่อครั้ง แล้วข้อขัดแย้งก็งอกกลับ

## หลักฐานที่ทำให้ตั๋วนี้เกิด (ยืนยันแล้ว 2026-09-05)

- `.agents/rules/rules-ai-agent.md:29` สั่งเอเจนต์ให้ **"ในทุกๆ Turn ที่เป็นงานซับซ้อน ต้องเปิดอ่าน `GEMINI.md` เพื่อทวนสอบกฎเหล็ก"** — ชี้ไปที่รัฐธรรมนูญที่ถูกแทนที่แล้ว
- `docs/development/architecture.md:4` เรียกเกณฑ์ 72% ว่า **"กฎเหล็ก ... ตาม GEMINI.md"** — ชั้น `docs/` อ้างอำนาจจากฉบับที่ถูกปลด
- `CLAUDE.md` เปิดหัวเองว่า GEMINI.md "kept as reference material — this file is the one Claude Code actually loads" แต่ไม่ได้ประกาศว่า **ห้ามใช้ GEMINI.md เป็นแหล่งกฎ** และไม่มีใครไปแก้ `rules-ai-agent.md` ให้เลิกชี้

## เกณฑ์ว่าตอบครบ

- [x] ตอบได้ว่าข้อความเชิงกฎซ้ำได้หรือไม่ และถ้าซ้ำได้ ที่รองต้องมีรูปแบบอย่างไร
- [x] ลำดับศักดิ์นี้ถูกเขียนลงในที่ที่ชนะเอง (ไม่ใช่เขียนไว้ในตั๋วนี้เท่านั้น)
- [x] เขียนแบบที่เอเจนต์เซสชันหน้าอ่านแล้วตัดสินได้ทันทีโดยไม่ต้องถามคน

## Resolution (2026-09-06)

**คำตอบ:** เอกสารในรีโปนี้แบ่งเป็น 4 หมวดที่ไม่แข่งกันข้ามหมวด (ขัดกันได้แค่ภายในหมวดเดียวกัน) — นิยามเต็มอยู่ใน [CONTEXT.md](../../../CONTEXT.md):

- **Rule** (ข้อบังคับเชิงพฤติกรรม) — หัวโต๊ะคือ **`AGENTS.md`** ไฟล์ใหม่ที่รากโปรเจกต์ ไม่ใช่ CLAUDE.md อีกต่อไป เหตุผลคือ Antigravity IDE (เครื่องมือที่ใช้งานจริงคู่กับ Claude Code) อ่าน `AGENTS.md` โดยตรง แต่ไม่อ่าน `CLAUDE.md` เลย — รายละเอียดเต็มอยู่ใน [ADR 0001](../../../docs/adr/0001-single-canonical-rule-file.md)
- **Status** — หัวโต๊ะคือ `docs/CURRENT_STATUS.md`
- **Wayfinding** — `README.md`, `START_HERE.md`, `docs/INDEX.md` (ยังมีเนื้อ Rule/Status ปนอยู่ ณ ตอนปิดตั๋วนี้ — ให้[ตั๋ว 05](05-start-here-fate.md)จัดการ)
- **Memory** — ไม่อยู่ในการแข่งขันแย่งอำนาจเลย ไม่ว่าจะเขียนอะไรไว้ก็ตาม ผิดพลาดได้ ต้องตรวจกับของจริงก่อนเชื่อเสมอ

**กฎการซ้ำ:** ห้ามพิมพ์ซ้ำเนื้อกฎเต็ม — ไฟล์อื่นอ้างได้ด้วยลิงก์ + สรุปหนึ่งบรรทัดเท่านั้น ยกเว้นไฟล์ลูกน้องที่ `AGENTS.md` ชี้ไปหาเองอยู่แล้ว (`rules-windows.md`, `rules-supabase.md`, `rules-thai-product.md`, `rules-git-hygiene.md`) ซึ่งถือเป็น "บ้านของกฎนั้น" ไม่ใช่สำเนา

**สิ่งที่ทำไปแล้ว (ตั๋วนี้ลงมือแก้ ไม่ใช่แค่ตัดสินใจ ตาม Notes ของแผนที่):**
1. สร้าง `AGENTS.md` — ย้ายเนื้อหาทั้งหมดของ `CLAUDE.md` มาไว้ที่นี่ + เพิ่มหัวข้อ "Document hierarchy" ชี้ไป CONTEXT.md/ADR
2. เขียน `CLAUDE.md` ใหม่ให้เหลือแค่ `@AGENTS.md` (import บรรทัดเดียว) — Claude Code ไม่รองรับ `AGENTS.md` เอง (ยืนยันจาก web search ก.ค. 2026) วิธีนี้คือ workaround ที่มีเอกสารรองรับ
3. สร้าง `CONTEXT.md` — นิยาม 4 หมวด
4. สร้าง `docs/adr/0001-single-canonical-rule-file.md`
5. แก้ `.agents/rules/rules-ai-agent.md:29` — เลิกชี้ไป GEMINI.md, ชี้ AGENTS.md แทน
6. แก้ `.agents/rules/rules-antigravity.md` — เอาตัวอย่างที่อ้าง spec ที่ถูกลบไปแล้วออก
7. แก้ `docs/INDEX.md` — path `API_ARCHITECTURE.md` ที่ผิด, ตัวชี้ GEMINI.md, ลิงก์ตายไป SUPABASE_SYSTEM_ARCHITECTURE.md, ลายเซ็น Gemini CLI Agent เก่า

**ยังไม่ได้ยืนยันจริง (ระบุไว้ตรงๆ ใน ADR ด้วย):** กลไก `@AGENTS.md` import อ้างอิงจากรายงานชุมชน ไม่ใช่ทดสอบเองในเครื่องนี้ — **ต้องเปิดเซสชัน Claude Code ใหม่แล้วถามว่าเนื้อหาใน AGENTS.md (เช่น หัวข้อ Windows/PowerShell) โผล่มาไหม** ก่อนถือว่าเรื่องนี้ปิดสนิท
