## Question

ตัวเลข **"72%"** กระจายไปทั่วรีโปในสามความหมายที่ต่างกัน จะยุบเหลือ **ข้อความเดียว เก็บที่เดียว** ว่าอย่างไร และที่เหลือทั้งหมดจะกลายเป็นอะไร

สามความหมายที่ปนกันอยู่ตอนนี้:
1. **เกณฑ์บังคับ** — "ห้ามต่ำกว่า 72%" (กฎที่ต้องผ่านก่อน commit)
2. **ค่าที่วัดได้** — 72.3% บน test set 595 รายการ เมื่อ 2026-08-26
3. **ตัวเลขปลอม** — 72% ที่ `tests/benchmark_similarity.py` เคย print แบบ hardcode โดยไม่ได้จัดหมวดอะไรเลย (ไฟล์ถูกลบแล้ว)

เอกสารเก่าแทบทุกฉบับพูดแบบที่ 1 หรือ 3 โดยไม่รู้ตัว

## Resolution (2026-09-06)

**ถ้อยคำเดียว:** "ห้าม regress จาก baseline ที่วัดได้จริงในเทสต์ (`tests/integration/test_classification_accuracy.py`) — ตัวเลขและเกณฑ์อยู่ที่ AGENTS.md กฎเหล็กข้อ 6" แทนที่ "≥72%"/"ไม่ต่ำกว่า 72%" ทุกจุดที่เป็นกฎบังคับ ไม่มีที่ไหนพิมพ์ซ้ำตัวเลขคงที่อีก — ทุกจุดลิงก์กลับ AGENTS.md เดียว (single-home+link policy จากตั๋ว 01)

**คำตอบ 2 คำถามย่อย:**

1. **hardcode ตัวเลขที่วัดได้ในเอกสารได้ไหม:** ได้ — **ถ้ามีวันที่+อ้างอิงเทสต์กำกับ** (แบบที่ `AGENTS.md`/`docs/CURRENT_STATUS.md:13` ทำอยู่แล้ว: "72.3% วัดจาก test set 595 รายการ (2026-08-26)") ตรวจแล้วว่า `docs/CURRENT_STATUS.md:213` ("ตั้งใจไม่โชว์ 72.3%") **ไม่ใช่กรณีเดียวกัน** — บรรทัดนั้นพูดถึงหน้าแดชบอร์ด **live ที่ query DB สด** ซึ่งเลขจากเทสต์จะเน่าเทียบกับข้อมูลสดจริง ส่วนเอกสารนิ่งที่ระบุวันที่ชัดเจนเป็นบันทึกประวัติศาสตร์ที่ถูกต้อง ไม่ใช่ปัญหาเดียวกัน — **ไม่ขัดกันจริง** เป็นความเข้าใจผิดตอนตั้งตั๋ว จึงไม่ต้องแก้ทั้งสองไฟล์นั้น
2. **เกณฑ์บังคับ:** "ห้ามต่ำกว่าค่าที่เทสต์บันทึกไว้" (ให้เทสต์ถือตัวเลข) — ไม่ใช่ตัวเลขตายตัวในเอกสาร ตรงกับ AGENTS.md กฎเหล็กข้อ 6 ที่ตัดสินไว้แล้วตั้งแต่ตั๋ว 01 อยู่แล้ว ตั๋วนี้แค่ทำให้ทุกจุดพูดตรงกัน
