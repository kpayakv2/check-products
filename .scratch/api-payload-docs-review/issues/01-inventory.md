## Question

พื้นผิว API ทั้ง 5 ชั้นมี endpoint อะไรบ้างจริงๆ แต่ละเส้นมีใครเรียก และเอกสารไฟล์ไหนบ้างที่พูดถึงมัน — สร้าง [`matrix.md`](../matrix.md) ที่มีแถวครบทุกเส้นแต่ช่องมิติยังว่าง เพื่อให้ตั๋วรีวิวทุกตั๋วมีรายการตายตัวให้ไล่ ไม่ใช่ไล่จากความจำ

## ต้องได้อะไร

ไฟล์ `matrix.md` หนึ่งไฟล์ ประกอบด้วย:

1. **ตารางเมทริกซ์** — หนึ่งแถวต่อหนึ่ง endpoint (method + path, หรือชื่อ ws message, หรือ PostgREST table+operation ที่ frontend เรียกตรง) คอลัมน์:
   - ชั้น (1–5 ตาม map Notes), ไฟล์:บรรทัด, ชนิด payload (JSON/multipart/stream/ws), อ่าน/เขียน
   - type ที่ประกาศของ request/response (ชื่อ Pydantic model / TS interface + ไฟล์) หรือ "ไม่มี"
   - ผู้เรียก (ไฟล์:บรรทัด ทุกจุด) หรือ "ไม่พบผู้เรียก"
   - เอกสารที่อ้างถึง (ไฟล์:บรรทัด)
   - 8 ช่องมิติ — **เว้นว่างทั้งหมด** ตั๋ว 03–07 จะเติม
2. **ข้อกล่าวอ้างในเอกสารที่ไม่ตรงกับแถวใด** — endpoint ที่เอกสารพูดถึงแต่ไม่มีในโค้ด แยกเป็นตารางย่อย (ตั๋ว 07 ใช้)
3. **ขนาดต่อชั้น** — จำนวน endpoint และขนาดโค้ดโดยประมาณ พร้อมความเห็นว่าชั้นไหนใหญ่เกินหนึ่งเซสชันรีวิว (~100K tokens) และควรแตกอย่างไร
4. **รูปแบบที่พบบ่อย** — envelope ของ response, รูปแบบ error, status code ที่ใช้ — นับเป็นตัวเลขว่าแบบไหนกี่เส้น (ตั๋ว 02 ใช้ตัดสินเกณฑ์)

## ข้อห้าม

- ห้ามประเมินมิติใดๆ ในตั๋วนี้ — แค่สำรวจ ถ้าเห็นปัญหาชัดให้จดเป็นหมายเหตุท้ายไฟล์ ไม่ใช่เติมในช่องมิติ (ยกเว้น P0 → ทำตามข้อยกเว้นใน map Notes)
- ห้ามยิง request ใดๆ — ตั๋วนี้อ่านโค้ดอย่างเดียว

## Resolution (2026-10-11)

สร้าง [`matrix.md`](../matrix.md) ได้ **103 แถว** ช่องมิติว่างทุกช่อง:

| ชั้น | แถว | หมายเหตุ |
|---|---|---|
| 1 FastAPI | 24 | 23 เส้นจาก decorator + `/docs`/`/redoc`/`/openapi.json` |
| 2 Next.js | 25 | handler ที่ export จาก route 16 ไฟล์ |
| 3 Edge Functions | 3 | — |
| 4 PostgREST/Storage ตรงด้วย anon | 44 | 8 เรียกจาก component · 14 ผ่าน `DatabaseService` ที่มีผู้เรียก · **22 เมธอดของ `DatabaseService` ที่ไม่มีผู้เรียก** |
| 5 WebSocket | 7 | `/ws` + ข้อความ 6 ชนิด **ไม่มีผู้รับฝั่ง client เลย** |

**การนับเทียบ:** route file 16 → handler 25 ✓ · decorator ใน `src/api` 24 = 23 HTTP + `/ws` ✓ · Edge 3 โฟลเดอร์ ✓ · `.from(`/`.rpc(` ใน `components/`, `app/` (นอก `app/api/`), `utils/supabase.ts` ครบ

**ไม่มีผู้เรียกในแอป (ป้อนเข้ามิติ 6):** ชั้น 1 = 9 เส้น (L1-01, 03, 04, 05, 07, 08, 11–13 · บางเส้นมีแต่เทสต์) · ชั้น 2 = 6 เส้น (L2-12, 13, 14, 16, 19, 20 · GET `/api/taxonomy` และ `/api/synonyms` ไม่มีใครเรียกเพราะหน้าเว็บเรียก `DatabaseService` ตรง) · ชั้น 3 = ทั้ง 3 ตัว (มีแต่สคริปต์) · ชั้น 5 = ทั้งหมด

**เอกสารที่อ้าง endpoint ที่ไม่มีอยู่:** 16 กลุ่ม (ส่วนที่ 2 ของ matrix) เช่น `/api/import/process*`, `/api/import/pending`, `/api/products/[id]/review`, `/api/status`, Edge function ที่ถูกลบไปแล้ว 4–6 ตัว และ `taxonomy-app/utils/api.ts` (ไม่มีใคร import) ที่เรียก Edge function ที่ไม่มีอยู่ 6 ตัว

**การแตกตั๋ว:** ไม่ต้องแตกตอนนี้ ชั้นที่ใหญ่สุดคือ FastAPI (≈2,190 บรรทัด, `internal_match.py` 853 บรรทัด) ยังอยู่ในหนึ่งเซสชัน ถ้าตั๋ว 03 ต้องไล่ลึกเข้า `src/services/` จนเกินขอบ ให้แตกเป็น (a) `internal_match` + `classify` (b) ที่เหลือ ตามส่วนที่ 3 ของ matrix — fog "ชั้นไหนต้องแตกตั๋วเพิ่ม" ใน map จึงถูกเคลียร์ออก

**รูปแบบที่ป้อนตั๋ว 02:** FastAPI คืน model ตรงไม่มี envelope + error `{detail}` · Next.js ใช้ `{success, data?, error?}` ทุก handler แต่ key ข้างๆ ไม่สม่ำเสมอ · zod ใช้แค่ 8/25 handler · ฝั่งผู้เรียกแทบทุกจุด parse คำตอบเป็น `any`

**สงสัย P0 (ยังไม่ยืนยัน ไม่ได้ยิง request):** FastAPI bind `0.0.0.0:8000` + CORS `*` + ไม่มีการยืนยันตัวตน → เส้นที่เขียนข้อมูล (L1-14 เขียน `keyword_rules`, L1-15 เทรนโมเดลใหม่) ยิงตรงที่ `:8000` ได้โดยไม่ผ่าน `middleware.ts` ยิงจาก LAN ได้จริงไหมขึ้นกับ Windows Firewall ซึ่งยังไม่ได้ตรวจ — ส่งต่อตั๋ว 03 และรายงานผู้ใช้ตามข้อยกเว้น P0 ใน map Notes · ข้อสังเกตอื่นอีก 9 ข้ออยู่ท้าย matrix
