## Question

สำหรับ 8 มิติใน map Notes อะไรคือเกณฑ์ที่ทำให้ช่องหนึ่งช่องได้ค่า `ผ่าน` — โดยเฉพาะมิติที่ต้องมี "แบบมาตรฐาน" ก่อนถึงจะบอกได้ว่าอะไรเบี้ยว:

- **มิติ 5 (สัญญา error):** status code ไหนถูกสำหรับกรณีไหน, error body หน้าตาแบบไหน, PostgREST คืน `200 []` / `204` แบบไม่ได้ทำอะไรต้องถูกตรวจจับอย่างไรถึงนับว่าผ่าน
- **มิติ 7 (รูปแบบ):** envelope มาตรฐาน (`{data, error}` หรือคืน object ตรง), ข้ามรอยต่อ Python↔TS ใช้ `snake_case` หรือ `camelCase` และแปลงที่ไหน
- **มิติ 3 (input):** "ตรวจแล้ว" หมายถึง Pydantic/zod เท่านั้น หรือ manual check ก็นับ
- **มิติ 4 (สิทธิ์):** เส้นอ่านอย่างเดียวที่เปิดโล่งนับว่าผ่านไหม (ใน LAN ออฟฟิศ ไม่มีล็อกอินจริง)
- **มิติ 8 (เทสต์):** อย่างน้อยกี่เทสต์ ชนิดไหน (unit / integration / e2e) ถึงนับว่าครอบ

เกณฑ์ต้องใช้ข้ามชั้นได้ เพื่อให้เมทริกซ์เทียบกันได้

## ข้อมูลตั้งต้น

ส่วน "รูปแบบที่พบบ่อย" ใน [`matrix.md`](../matrix.md) — เลือกมาตรฐานจากแบบที่โค้ดใช้มากที่สุดก่อน เว้นแต่แบบนั้นผิดเชิงวิศวกรรม

## เกณฑ์ว่าตอบครบ

- [x] ทุกมิติ 1–8 มีเกณฑ์ผ่านเขียนเป็นประโยคที่ตรวจได้ (ไม่ใช่ "ควรดี")
- [x] เกณฑ์ถูกเขียนลงหัว `matrix.md` (ไม่ใช่แค่ในตั๋วนี้) ให้ตั๋ว 03–07 อ่าน
- [x] ผู้ใช้ยืนยันแล้ว

## Resolution (2026-10-11)

ผู้ใช้ตอบ "ตามนั้น" รับเกณฑ์ตามที่เสนอทั้ง 8 มิติ เกณฑ์ฉบับเต็มอยู่ในหัว [`matrix.md`](../matrix.md) หัวข้อ "เกณฑ์ผ่านต่อมิติ" จุดตัดสินหลัก: error ต้องสม่ำเสมอภายในชั้น ไม่ต้องข้ามชั้น · wire format เป็น `snake_case` · เช็ก input ด้วยมือนับได้ถ้าครอบทุกกรณีและคืน 4xx · เส้นที่อ่านด้วย `supabaseAdmin` ต้องอยู่ใน `GATED_READ_PATHS` · ช่องเทสต์ที่ไม่ผ่านเป็น P3 เสมอ
