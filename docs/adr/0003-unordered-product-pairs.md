# คู่สินค้าไม่มีลำดับ — กันซ้ำแบบไม่สนลำดับ แต่ไม่บังคับให้บรรทัดเรียงตามไอดี

`similarity_matches` มี `UNIQUE (product_a_id, product_b_id)` ซึ่งไวต่อลำดับ แต่ละเส้นทางเขียนคู่ในลำดับของตัวเอง สคริปต์สร้างคิวเขียนตามลำดับที่สแกนเจอ ส่วนปุ่มรวม/แยกในหน้าตรวจซ้ำเรียงตามไอดี ผลคือ 31 คู่มีสองบรรทัด (บรรทัดคิวที่ยังไม่ตรวจ + บรรทัดที่คนตัดสินแล้ว) ตามนิยามใน `CONTEXT.md` **คู่สินค้า** ไม่มีลำดับและมีคำตัดสินของคนได้อันเดียว เราจึง**เพิ่ม unique index บน `(LEAST(a,b), GREATEST(a,b))`** และให้ผู้เขียนค้นบรรทัดเดิมทั้งสองลำดับก่อนเขียน โดย**คงลำดับที่เก็บไว้ในบรรทัดเดิม**

## Considered Options

- **บังคับให้ทุกบรรทัดเรียงตามไอดี (`CHECK (product_a_id < product_b_id)`) แล้วสลับบรรทัดเก่าราว 940 บรรทัด**: ดูง่ายกว่า เพราะ unique เดิมจะกลายเป็นแบบไม่สนลำดับเอง แต่เราปฏิเสธทางนี้ เพราะคู่จากขั้นนำเข้า (`import_wizard_dedup`) ใช้ลำดับบอกว่า `product_a_id` คือสินค้านำเข้าและ `product_b_id` คือของในสตอก (`scripts/reroute_import_batch_by_rule.py` หาด้วย `product_a_id`) ถ้าสลับลำดับ ข้อมูลนี้จะหายโดยไม่มีอะไรเตือน **อย่า "ทำให้ง่ายขึ้น" ด้วยการบังคับเรียงลำดับ** จนกว่าคู่จากขั้นนำเข้าจะเก็บข้อมูลว่าฝั่งไหนคือสินค้านำเข้าไว้ในช่องของตัวเอง
- **แก้แค่ฝั่งผู้เขียน ไม่แตะ schema**: ปุ่มรวม/แยกเรียงไอดีอยู่แล้ว แต่ก็ยังเกิดบรรทัดซ้อน ผู้เขียนใหม่ทุกตัวจะต้องจำกฎนี้เอง ฐานข้อมูลควรเป็นผู้ปฏิเสธคู่ซ้อน ไม่ควรพึ่งให้ผู้เขียนแต่ละตัวทำถูก
