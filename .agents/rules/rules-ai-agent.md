# 🤖 AI Agent Execution Rules & Code of Conduct

กฎชุดนี้สร้างขึ้นเพื่อกำกับดูแลพฤติกรรมการทำงานของ AI เอเจนต์ทั้งหมดในระบบ ป้องกันไม่ให้เกิดปัญหาลืมบริบท คาดเดาข้อมูลโดยไม่มีหลักฐานอ้างอิง หรือสร้างความเสียหายให้กับส่วนอื่นๆ ของระบบ

---

## 🚫 1. ห้าม "คิดไปเอง" (No Base-less Assumptions)
* **ต้องอ่านโค้ดจริงทุกครั้ง:** ห้ามคาดเดาสถานะของตัวแปร โครงสร้างฟังก์ชัน หรือโครงสร้างของโฟลเดอร์จากคำอธิบายของผู้ใช้หรือความจำเก่าของโมเดล เอเจนต์ต้องใช้เครื่องมือ `view_file` หรือ `grep_search` เพื่อตรวจสอบโค้ดล่าสุดจากไฟล์จริงก่อนตัดสินใจเสมอ
* **ห้ามเดาผลการเชื่อมต่อ:** ห้ามระบุว่าฐานข้อมูลหรือ API เชื่อมต่อสำเร็จจนกว่าจะได้รันจริงและเห็นผลลัพธ์การตอบรับจากระบบเครือข่าย

## 📡 2. ตรวจสอบผลกระทบอย่างเคร่งครัด (Assess Blast Radius)
* **ค้นหา Callers ก่อนการแก้ไข:** เมื่อต้องแก้ไขฟังก์ชัน คลาส หรือโมดูลใดๆ ต้องทำการประเมินผลกระทบ (Blast Radius) เสมอ โดยการสืบค้นว่ามีจุดใดในระบบบ้างที่เรียกใช้งานเป้าหมายนั้น
* **ใช้ MCP Socraticode ในการตรวจสอบเป็นลำดับแรก:** บังคับให้เอเจนต์เรียกใช้เครื่องมือของ **Socraticode** เช่น `codebase_impact` (เช็คผลกระทบลูกโซ่), `codebase_symbol` (ค้นหานิยามตัวแปร/ฟังก์ชัน), `codebase_search` (ค้นหาแพทเทิร์นโค้ดในระบบ) หรือ `codebase_graph_circular` (ตรวจเช็คการอ้างอิงแบบวงกลม) เพื่อให้เห็นบริบทของโค้ดจริงรอบด้านแบบ 100%
* **ใช้ Grep Search ควบคู่กัน:** ใช้ `grep_search` ค้นหาคำหรือประโยคเฉพาะเจาะจงร่วมด้วยเพื่อความแม่นยำสูงสุด

## 🧠 3. การควบคุมบริบท (Context Recency & Anchoring)
* **หมั่นทบทวนรัฐธรรมนูญ:** ในทุกๆ Turn ที่เป็นงานซับซ้อน เอเจนต์ต้องเปิดอ่าน `GEMINI.md` เพื่อทวนสอบกฎเหล็กของโปรเจกต์ (เช่น การบังคับใช้ `127.0.0.1` บน Windows หรือการใช้ `ThaiTextProcessor`) เพื่อให้มั่นใจว่าจะไม่ละเมิดข้อตกลงกลางคัน
* **ประหยัดพื้นที่จำลอง (Context Preservation):** หลีกเลี่ยงการเปิดไฟล์ใหญ่เต็มรูปแบบหลายๆ รอบ ให้ระบุเฉพาะช่วงบรรทัด `StartLine` และ `EndLine` ในการอ่านจุดเฉพาะหลังจากการสำรวจเบื้องต้น เพื่อลดการขยายตัวของ Token และป้องกันข้อมูลแรกเริ่มหลุดออกนอกหน้าต่างบริบท

## 📝 4. บันทึกสิ่งทีทำอย่างมีระเบียบ (Structured Logging of Actions)
* **ยึดมั่นใน Artifacts:** ทุกครั้งที่เริ่มการพัฒนาระดับฟีเจอร์หรือการแก้ไขที่สำคัญ ต้องสร้างและอัปเดต `task.md` ทันทีเพื่อบันทึกสถานะงานให้ชัดเจน
* **สรุปการเปลี่ยนแปลงใน Walkthrough:** หลังการทำงานเสร็จสิ้นหรือเมื่อหมดคาบการทำงาน เอเจนต์ต้องเขียนบันทึกสรุปความเปลี่ยนแปลง ผลการทดสอบ และหลักฐานใน `walkthrough.md` เพื่อให้เอเจนต์ตัวถัดไปรับไม้ต่อได้อย่างราบรื่นโดยไม่ต้องถามซ้ำ

## ✅ 5. Self-Alignment Checklist (ถามตัวเอง 5 ข้อก่อนส่งงาน)
ก่อนจะสรุปและส่งงานกลับคืนให้คุณกาน (Karn) เอเจนต์จะต้องตอบคำถามเหล่านี้กับตัวเองให้มั่นใจก่อน:
1. **[ ] เราได้ตรวจสอบโค้ดจริงในจุดแก้ไขล่าสุดหรือยัง?** (ไม่ใช่เดาจากหน่วยความจำเดิม)
2. **[ ] เราตรวจสอบผลกระทบลูกโซ่ (Blast Radius) ของการแก้ไขจุดนี้ด้วย MCP Socraticode ครบถ้วนแล้วหรือยัง?**
3. **[ ] ผลการรันเทสหรือการทำงานจริงไม่มีความผิดพลาดใดๆ บน Windows ใช่ไหม?** (มีจุดผิดปกติเรื่อง localhost/127.0.0.1 หรือไม่)
4. **[ ] เราบันทึกและอัปเดตสถานะใน `task.md` และ `walkthrough.md` ครบถ้วนแล้วหรือยัง?**
5. **[ ] เราใช้เครื่องมือ Socraticode (เช่น codebase_search, codebase_impact, codebase_symbol) ช่วยค้นคว้าตรวจสอบอย่างถี่ถ้วนแล้วหรือยัง?**
